# 产教融合：工作结构背后的业务规律

来源：journal qtclass/ 2026-08 ~ 09 复盘讨论，与创始人对话确认（2026-09-04）

## 结构事实

- journal 分三条业务线（qtclass / qtcloud / qtdata），事实源是同一个群——量潮实训基地飞书群
- qtcloud 的产品发布（执行云 v0.1）、qtdata 的课题（流程状态数据底座）、商务方向（盟友对接中小企业）都从实训基地群流出
- 学员课题直接是真实业务需求；公司以数据、文档、资源支持学员交付
- 治理下放持续加速：立项初审 → 结项初审 → 证明签发 → 规则生成权，两天走完

## 产教融合：产与教是同一过程的两面

- 「教」端：课堂、实训基地（qtclass）——客户是学员与高校
- 「产」端：执行云（qtcloud）、数据积木（qtdata）——客户是企业
- **融合点：教育用真实业务当教材，产业用学习过程当交付**（创始人定性：「这就是我们组织模式的精髓」）

推论：

1. **单一事实源的原因**：实训基地群是产与教的交汇点，学员从「学习者」到「交付者」的边界连续。三线分开记账，是因为产、教两端各有各的客户与账本，但事实流是同一条
2. **互为生产资料**：对称的融合，不是主从——教育不是人才管道，产业不是教学场景
3. **商业本质**：成本中心与利润中心互相转化——交付人力是「在学习中的学生」，学习产出是「交付成果」。这解释了以有限人力做出大量创新成果的可行性
4. **制度接口**：教学实习证明（浙理工生产实习课程制度）、众包、课题、代金券、招聘考核（甲方视角评估真实成果）

## 实训基地脱离公司：账本上多了一个主体

治理下放不是公司内部的授权改革——**下放的不是权力，是主体资格**。实训基地成为独立治理主体，证据链：

- **审批序列即主权声明**：Demo「先向代表大会提交，然后再给公司提交」——代表大会是第一审批主体，公司退到第二道；科层内放权不会改变审批顺序
- **资质权移交**：实训/实习证明的规则与签发归代表大会——实训基地有自己的资质体系
- **规则生成权**：立法权在实训基地内部生成，不从公司继承
- **组织空间**：「量潮创新联盟-实训基地」部门群——组织架构上有了自己的户籍

两个主体的关系：

- **代表大会** = 实训基地的政府——代表后备役锻炼的是治理自己的组织，不是晋升公司科层
- **公司** = 相邻主体：实训基地的第一批委托方与兜底方
- **产教融合的精确形态** = 两个主体之间的接口——课题、众包、代金券、证明是接口协议；公司是实训基地的第一个客户（8-30 商业化悬念的答案形状）
- **冲突解决** = 外交而非内政：决议与公司利益冲突时，靠谈判、契约、交换，而非服从、否决；「一票否决但很少用」如宗主国否决权——存在维持秩序，使用伤害关系

## 常见误读

- ✗「业务线是观念切分，对话才是组织的真实形态」——三条业务线各有真实客户与收入，产业端是真实生意
- ✗「人才供应链是主信道，业务是它的外溢」——产业不是教育的副产品，两者互为生产资料
- ✗「治理下放是公司内部的授权改革」——下放的不是权力，是主体资格

## 一句话

工作结构不是公司的信息管理方式，而是产教融合战略在信息层面的投影——组织怎么记账，由业务怎么融合决定。而产教融合走到深处，是**账本上多了一个主体**：实训基地若继续脱离，qtclass 账本要拆出自己的账本。
