# 制度生成的社会路径：成员发明、公司追认

> 证伪时限：2026-12（第一形态）／2027-03（第二形态·标准倒挂）
> 来源：journal qtclass 2026-09-10 ~ 14（积分制→代金券转赠、分包→独立账本、知识库→客服档案初稿）、2026-09-21 ~ 23（第二大脑与协作流自建、准入门槛自主、研发难题外派）；深化「权随能授」（qtacademy-evolution）与「复现即成熟」（量潮云体系总述）。

## 感知现实

9-10 一天之内链条完整走完：上午课题作者发布分包体系（设计 PR 竞争、四方评审 + CI、30 天释放、仪表盘记分），中午创始人点破「积分就是代金券制度的雏形，早期人工助研就是这样设计的」，下午授权独立账本，晚上另一名成员起草账本草案。此前的同类样本：新人知识库提议 → 客服支持档案初稿；课题互助 → 代金券转赠规则。9-21 该模式从制度延伸到**生产资料**：主席申请、公司授予独立 GitHub Org，「你们可以自由制定你们的管理规则，公司只管 Owner」——基础设施的主权也走同一条「申请 → 授予」的路径。

9-21 ~ 23 又推进两格：

- **自建而非申请**：基地不再等公司授予，自己建起「第二大脑 + 协作流 + 规章」（仓库 `quanttide-training`）——创始人的角色只是「强烈建议」与用词校准（「academy 是学院的意思」）
- **难题外派**：创始人把自己啃了一周没啃下来的「知识工作建模」难题移交基地当课题，「这个就给实训基地研究了」——外派的从制度、生产资料，扩到了研发难题本身

## 理解抽象

制度不是被设计的，是被「追认」的：成员在真实需求压力下发明制度雏形，公司在雏形被验证后命名、接认、接进正式制度。「权随能授」的姊妹规律是**制随需生**——规则先在解决问题的位置上长出来，然后才被承认为规则。这与「复现即成熟」同构：市场会重演的制度才值得产品化，社区已重演的制度才值得追认。

## 预测

**我们预测：这个组织的新正式制度将越来越多以「追认」而非「设计」的方式产生——公司的制度需求单，将主要来自对社区自发生成机制的识别与命名。**

- 可证伪：若未来一个季度内，主要制度仍由公司预先设计再推行、社区自发制度占比持续走低，则预测错误
- 若真：公司的制度工作重心从「制定」转向「扫描与追认」；评估社区健康度的核心指标变成「制度雏形的自发产出率」
- 点名：预言「公司发布制度、社区执行」的单向模式在自治组织里死亡——它只在两处还有位置：安全红线与财务兜底

## 第二形态：标准倒挂

9-21 创始人下放准入门槛时给出一句新话：「实训基地正式成员的准入门槛，你们可以自己定啊……**公司会根据你们摸索出来的这个免费学员的入门门槛，来决定公司的政策**」。

此前追认的对象是「一条制度」（转赠规则、账本草案）；现在追认的对象升到「一套标准/政策依据」——基地制定的门槛反向成为公司的对外政策。这完成了授权方向的翻转：此前下放的都是基地内部事务的自有权（初审、立法、运营、人事、账本、代码 Org），基地是「被授权的自治体」；标准倒挂意味着基地开始扮演**标准的输出方**，公司退向「资源获取（老师、订单）+ 兜底」。

**我们预测：实训基地将演化为「标准输出方」——公司对外的培训/招聘/众包政策将越来越多地引用基地摸索出的门槛与规则，政策来源从公司单向发布反转为下游供给。**

- 可证伪：若未来一个季度内，公司政策仍全部由公司内部起草、基地标准仅限基地内部使用，则预测错误
- 若真：公司的培养政策（免费学员门槛、评审标准、代金券规则）应以基地运行结果为准，而非公司起草，「公司内部起草培养政策」这个环节应从流程中删除
- 点名：预言「公司制定政策、社区遵守」的方向死亡
