# 社区从用积木到造积木

> 命题：社区产物从「课题交付物」升级为「基础设施」——当社区开始生产新积木、且无需手把手教就能对齐契约接口时，生态具备了自长大的条件。

来源：journal qtclass/qtcloud/2026-09-07 ~ 09-08 的两个实证

## 两个实证

**第二大脑创建工具**（学员开发）：中文页面填写需求、检查命名、本地建立第二大脑仓库、保存验收意见。关键的不是功能，是它交卷的方式——contract.yaml（6 个资产 + 技能）与资产云 CLI 一次性对齐，作者自己源码编译 Rust CLI 实测 config 识别通过。CEO 助理的答复确认：**资产云唯一认可的接入方式就是契约登记，格式对齐即接入成立，无需额外文档**。

**流程状态解析器**（课题作者开发）：从解析单封邮件升级为解析整份项目复盘——按时间线拆出多条状态记录、每条带原文证据可追溯；真实脱敏样本 17 条时间线节点识别全部命中。作者主动征集真实样本校准。

## 为什么是质变

8-29 的预言是「社区在量潮积木上排列组合」——第一代验证是学员拼装已有积木产出洞察与交付物。这一轮的不同在于：

1. **产物性质变了**：不再是「完成任务的交付物」，而是别人可以继续用的工具——第二大脑工具会成为其他人创建第二大脑的入口，解析器会吃掉全组织的复盘报告
2. **接口经受了首次真实接触**：契约登记不是设计文档上的设想，一位社区成员在没有手把手教学的情况下完成了对齐——只经过一轮答疑
3. **标准由社区自己携带**：作者问的是「测试组织用哪个、怎么接入」——问的是接口规范，不是要特权。**标准被写进契约之后，就不再需要人盯**

## 接口成熟度判据

生态能不能自长大，看的不是有多少人在用积木，而是**新积木能不能不经过中心审批就接入**：

| 阶段 | 特征 | 判据 |
|------|------|------|
| 用积木 | 社区拼装已有积木完成课题 | 有交付物 |
| 造积木 | 社区生产新工具并自主对齐契约 | contract.yaml 对齐即接入 |
| 换积木 | 社区提出契约本身的修订 | 出现第一份社区发起的契约修订 PR |

当前处于第二阶段。第三阶段（社区修订契约）值得留意——那将是契约治理权下放的信号，与代表大会的立法权同构。

## 与其他洞察的关系

- [课堂即创新实验室](../qtclass/classroom-as-innovation-lab.md)的「内部创业生态链」获得社区侧证据：生态不止吸纳人，开始吸纳物
- 资产云的契约登记与 [Outcome](../../../domains/quanttide-execute/data/intention/outcome.md) 同构：都是**用结构化记录替代人对人的信任判断**——接入看契约，验收看记录
- 与 [deplatforming-narrative](../qtcloud/deplatforming-narrative.md) 呼应：自有平台的价值在于接口是自己的——社区对着自己的契约对齐，而不是对着大厂的黑箱猜测

---

**一句话**：判断一个生态是否成立，看它是否已经出现「未经中心推动、按公开契约自行接入」的第二件作品——第二大脑工具就是那件作品。
