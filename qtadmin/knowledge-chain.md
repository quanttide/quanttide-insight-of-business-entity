# 知识提炼链：从沟通语到共识

在沟通语里面形成共识，需要知识抽取的方法。管理后台的研发中落地了一条完整链路：把分散在聊天记录中的讨论提炼为可承载、可总结的政策知识。

## 链路

聊天记录 → 提取 → 本体 → 总结

- **connect 拉取**：跨群搜索聊天记录（群聊与单聊），讨论分散在多处，搜索聚合
- **acquire 提取**：LLM 从讨论文本中提取政策条目（name、description、source）
- **extract 本体**：逐条抽取结构化本体（条款、执行步骤、可编码性），并承载状态
- **summary 总结**：按主题归纳现有知识，输出 Markdown 总结

## 关键认知

- **模糊是合法承载状态**：政策讨论未收敛时，evolving 是被承载的真实状态，不是知识债务。不强制澄清，随实践自然迁移到 settled
- **状态是属性，不是组织维度**：总结按主题划分（主题是知识的组织维度），状态标注在条目上，不按状态分组
- **总结忠实于知识本身**：不添加知识之外的推断或建议，避免越权
- **领域层与执行入口分离**：lib 化后领域能力（connect、knowl）可被示例与其他消费者复用，CLI 只留执行入口

## 迁移

- 任何业务线的政策制定（招聘、课堂等），从沟通中形成共识的场景
- 知识提炼链的每一环都是独立的（提取、本体、总结解耦），可按需组合

## 边界

- 数据源依赖 lark-cli 可用性与搜索覆盖
- LLM 提取质量依赖提示词设计与原始数据质量
