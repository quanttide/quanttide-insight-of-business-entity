# 复制即备份，备份即归档

整个系统在不停地复制，复制的过程天然就是备份。备份出来了，数据就已经归档，归档之后就可以清理掉。

## 机制

- 系统复制 = 备份：每一份复制品都是数据的第二份存在，无需额外备份流程
- 备份 = 归档：数据被复制出来后，即进入归档状态，原始数据可以被处理
- 归档 = 可清理：飞书数据备份出来，这个数据就已经归档了，那就可以把它处理掉了
- 数字资产治理的作用是教会团队这个认知：知道什么时候该备份，备份后就可以清理

## 迁移

- 替代飞书和企业微信的流程：自研平台复制数据 → 备份即归档 → 清空后逐渐降低旧平台地位
- 任何数据迁移与平台替换场景：先复制再清理，复制本身是安全网

## 边界

- 复制不等于验证：备份需要校验可恢复性，否则复制只是幻觉
- 归档的清理需要治理规则：清理不重要的，保留有资产价值的

## 实现差距

asset 支柱在 CLI 已落地（archive 日志归档、status 结构合规检查、quality 语义质量评估），但资产建模未达意图：

- 内部资产三层建模（原始数据 assets、人类分析 data、总结知识 docs）未实现

- 起步路径（从导出飞书和 GitHub 数据开始，建立组织层面的分析工具）只部分落地（connect 聊天搜索）
